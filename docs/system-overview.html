③站长对账

记账主体是上游供应商（vendor），不是渠道。渠道通过「绑定」归属到某个上游，站内消费才算得到它头上。

记账的三样东西

💵

充值台账 手动

你给上游充的钱（充值 / 退款 / 扣减）。只有你知道，记在流水里。

⚖️

余额快照 自动

上游当前余额，由监控自动采集，每天落一行。

📈

站内消费 自动

你站内用户消耗的额度，从站内定时同步回来。

累计已用 = 累计净充值 − 当前余额

这是对账的核心恒等式。你充了多少（台账）、还剩多少（余额）一减，就是花掉了多少 —— 完全不依赖上游会不会清记录。

利润是怎么算出来的

# 单个上游 实际利润 = 站内消费 − 实际净充值 消耗差异 = 站内消费 − 上游已用 # 倍率差，毛利润来源 账账差异 = 当前余额 − (净充值 − 上游已用) # 应≈0，不为 0 说明账对不上 # 整站 预计已实现利润 = 提现 − 实际净充值 − 运营支出 预计结算利润 = 提现 − 外部未消费余额 − 实际净充值 − 运营支出

★核心原则：余额是锚

这是整套对账设计里最重要的一条。上游面板会清空充值 / 消费记录，但余额永远是对的。

🌊

流量：会消失

充值记录、消费记录 —— 上游一清就没了。不能依赖它们。

  • 充值 → 用自己的台账兜底
  • 消费 → 用余额差反推
⚓

存量：永远准

余额是「当下还剩多少」，上游不会清。它是唯一的锚。

  • 监控每 15 分钟采一次
  • 自动落成每日快照

怎么做到的

系统每隔 15 分钟，把监控采到的上游余额自动写进对账账本，并顺手用「累计充值 − 余额」算出累计已用。所以：余额不用手记、已用不用手抄，你只管记充值流水。

快照策略：明细会删，汇总永留

高频采样（明细）

余额、消费每 15 分钟一个点。只用于画当天的曲线，过期按策略自动删除（余额留 90 天、日志留 30 天）。

日汇总（永久）

每天收尾时，把当天的落成一行：余额取末值、消费取总和。这一行永久保留，是对账的根据。

流水（永久）

充值、退款这类事件流水，打死不删。删了账就没了。
